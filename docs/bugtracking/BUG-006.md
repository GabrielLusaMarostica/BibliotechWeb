# BUG-006 – Pedidos simultâneos pelo mesmo livro causam deadlock (500)

- **Rótulos:** `bug`, `severidade: alta`
- **Encontrado em:** 2026-10-23 · **Origem:** Teste exploratório (concorrência)
- **Status:** corrigido e fechado

## Descrição
Com 8 pedidos ao mesmo tempo pelo último exemplar, o MySQL derrubava 6 transações por deadlock e a API respondia 500. O estoque ficava correto, mas o usuário não recebia "estoque insuficiente". Causa: a chave estrangeira de `item_emprestimo` pega bloqueio compartilhado na linha do livro e o `UPDATE` seguinte pede bloqueio exclusivo.

## Passos para reproduzir
1. Livro com 1 exemplar.
2. Disparar 8 `POST /api/emprestimos` ao mesmo tempo para esse livro.

## Resultado esperado
Um pedido com HTTP 201 e sete com HTTP 409 (estoque insuficiente).

## Resultado obtido
Um 201, um 409 e seis 500.

## Correção
A baixa de estoque passou a vir antes dos `INSERT`s, com os livros em ordem de id; além disso `ExecutorSql.emTransacao` repete a transação (até 3 vezes) quando o MySQL aponta deadlock (SQLSTATE 40001).

## Teste de regressão
Caso CT-X03 no MySQL real (resultado `[201, 409 × 7]`, repetido 3 vezes) e `RepositoriosJdbcTest.pedidosSimultaneosPeloUltimoExemplarDeixamUmSoVencedor` (no H2 o deadlock não se reproduz, então esse teste só protege a regra de estoque).
